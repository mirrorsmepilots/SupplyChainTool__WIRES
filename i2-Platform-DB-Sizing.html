Project SC-AI-01 · Database Sizing

i2 Platform — database sizing requirements

1 · Deployment path

Approach
The client's AWS account runs PostgreSQL on self-managed compute, not RDS.
Amazon EKS + the CloudNativePG operator (recommended) — an open-source Kubernetes operator for PostgreSQL. This is how i2's own staging and production environments run today. It handles replication, failover, connection pooling and backups declaratively.

2 · Compute sizing

Per node — resource requests and limits
ResourceBaseline (request)Burst (limit)
vCPU per node24
Memory per node4 GB8 GB

Applies to each of the two nodes (primary + replica). Total provisioned capacity across the pair is 4 vCPU / 8 GB at baseline, up to 8 vCPU / 16 GB at burst.

Suggested AWS instance types
Deployment pathInstance typeNotes
EKS worker node r6g.large (2 vCPU / 16 GB) or m6g.xlarge (4 vCPU / 16 GB) Memory-optimized preferred — PostgreSQL benefits from OS page cache headroom above the 8 GB container limit.
